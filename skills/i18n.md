# ÁTICA Calidad — translations

*Read this file before adding any user-facing text in a Twig template or a PHP
service.*

All UI strings are in Spanish (the application's target audience), under
`translations/*.es.yaml`, **one file per domain**: `admin.es.yaml`,
`calendar.es.yaml`, `centre_selection.es.yaml`, `command.es.yaml`,
`dashboard.es.yaml`, `emails.es.yaml`, `login.es.yaml`, `messages.es.yaml`,
`navigation.es.yaml`, `reports.es.yaml`, `search.es.yaml`, `security.es.yaml`,
`settings.es.yaml`.

There's no `trans_default_domain` configured. **The domain is always passed
explicitly** as the second argument of the filter:

```twig
{{ 'centre_profiles.title'|trans({}, 'admin') }}
```

When adding a new key, decide which domain file it fits based on functional area
(not on where it's used in code), and follow the section-prefix convention already
present in that file (e.g. `centre_profiles.*`, `settings.category.*`).

## Don't hardcode translatable content in PHP

Before writing an array of month names, weekday names, etc. inside a PHP service,
**check first whether it already exists** in `translations/*.yaml`. For example,
Spanish month names already exist as `month.1` .. `month.12` in
`calendar.es.yaml` — don't duplicate them as a PHP constant. This applies broadly
to any user-facing content: if a centre in a different region, or a deployment in
another language, would reasonably need to show it differently, it belongs in
`translations/`, not in code.
